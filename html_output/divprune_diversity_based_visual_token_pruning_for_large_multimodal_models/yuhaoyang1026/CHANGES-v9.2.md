# DivPrune v9.2：修复第 6 章筛选联动与 4.1 布局

基于 v9.1。配色、渐变、卡片质感、教学交互，以及屏外暂停、有限时长重绘、首页播完停止、播放速度选择、第 9 章实测 / 示意区分均保持不变
（修改后重跑 v9.1 的性能场景，结果与 v9.1 相同）。

## 一、第 6 章：上方总览与 6.1 面板的筛选联动

**原因**：6.1 的筛选条件只存在 6.1 组件内部，选中项却是两处共享；6.1 展示时用 `list.find(选中) ?? list[0]`。
当共享选中项不在当前筛选结果里（例如 6.1 选“一致”后在上方点“≠ 保留多少个”），6.1 会静默展示筛选结果的第一项，上下两处指向不同条目。

**修复**：把筛选条件也放进共享状态（`dp-codemap-data.ts`），并在每次变更时维持一条不变式——选中项一定属于当前筛选结果：
- 选中一条（上方总览或 6.1 列表都走 `selectCode`）：若当前筛选不包含它，筛选自动切回“全部”。
- 切换筛选（`setCodeFilter`）：若原选中项不在新结果里，改为选中新结果的第一项。
- 两处界面都只按选中 id 展示，6.1 不再回退到列表第一项。

**验证**（1280×720、1366×768、1440×900 各一遍，共 13 步）：
6.1 选“一致” → 上方点“≠ 保留多少个”（筛选切回“全部”，上下都是“保留多少个”，论文摘录含 91.2%、代码含 0.098）；
依次切换 全部 / 一致 / 有差异 / 论文未说明 / 公开代码缺失 / 全部；
有差异下点 6.1“TFLOPs 公式” → 上方点“批大小” → 6.1 切“一致” → 上方点“视频模型与效率脚本” → 6.1 点“索引与偏移”。
每一步核对：上方高亮项与说明、6.1 列表高亮、6.1 标题、状态、结论文字、筛选条件指向同一条记录。三种窗口下 13 步全部一致。

## 二、第 4 章 4.1：读数卡裁切与向量越界

**读数卡原因**：读数卡标题设为不换行，两张卡固定并排。1280 宽时正文区约 853px，按设计单位只剩约 1376（交互模块按 1472 书写），
右侧面板变窄，“卷尺：欧氏距离 ‖γ − ω‖”超出卡片并被外层裁掉。
复查时发现同一原因还影响另外 10 张卡片（1.1 / 3.1 / 7.1 / 7.2 / 封面的整宽画布，4.2 / 5.2 / 9.1 / 10.1 的读数，2.1 的表头），一并修复。

**读数卡修复**（字号不变，只改布局）：读数卡标题允许换行；两张卡用 `auto-fit` 网格，放不下时上下排列（1280、1366 下上下排列，1440 下并排）；
“左画布 + 右面板”的列宽改为可伸缩区间；9.1 / 10.1 的固定列改为可伸缩；2.1 表头允许换行；整宽画布作为图按卡片宽度等比缩小（画布外的文字字号不变）。

**向量越界原因**：原点在 x = 360、1 个单位 = 230px，夹角 180°、长度 1.60 时端点到 x = −8，箭头和“ω 队”标签在画布外。

**向量修复**：比例尺按允许的最大长度 1.6 固定：原点居中，1 个单位 = 180px（1.6 × 180 = 288px），左右各留约 90px 给箭头和标签；
改变长度时比例尺不变，可以直接比较长短。“卷尺”标签改放在线段法线方向、远离营地的一侧，两队几乎重合时不标。

**验证**（三种窗口各一遍）：夹角 0° / 90° / 180° × 长度 0.30 / 1.00 / 1.60 共 9 组——
所有线段端点与文字都在画布内，“γ 队 / ω 队 / 营地 / 罗盘 θ”标签都在；读数卡不越界、不裁切；
两个读数与公式一致（1 − cos θ、‖γ − ω‖）；同一夹角下改变长度，余弦距离不变。
