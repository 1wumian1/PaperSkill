# DivPrune v9.1：局部优化（性能 + 减少重复讲解）

基于 v9（`divprune-tutorial-v9.zip`）。配色、渐变、卡片质感、核心技术交互与证据说明保持不变。
对照 emilkowalski/skills 的 `animation-performance` 与 `review-animations`（含 STANDARDS.md）检查。

## 一、性能：先找原因，再改代码

| 位置 | 原因 | 修改前 | 修改后 |
|---|---|---|---|
| 公共画布 `useStage`（`src/modules/dp-kit.tsx`） | 每张画布挂载后无限 rAF 循环，屏外、静止画面也每帧重绘 | 全部章节展开时 22 个循环、每帧 21 张屏外画布重绘 | 按需绘制：只收 `ctx` 的画面视为静止，状态变化时画一次；用到 `t` 的画面在点击后播放 900ms 过渡，然后画最终状态并停止；屏外暂停，回到视口直接画出当前状态 |
| 滑块驱动的画布（3.1、2.1 等） | 画布用缓动追赶滑块值，松手后还在动 | 松手后 85 帧（约 1.4 s）才静止 | 滑块输入标记为“直接操作”，画布直接画到目标状态：1 帧 |
| 封面两侧点云（`dp-cover.tsx`） | `useTimeline` 每帧 `setState`，两个组件每帧重新渲染；且无限循环 | 循环一直播放 | 共享时钟对象（`dp-cover-clock.ts`）由一个 rAF 循环推进，画布订阅后直接重绘；React 只在“已选几个”变化时更新（每轮最多 16 次）；封面在视口内播放一次（6 s）后停在结果上，可“重播”；滚出视口暂停、回来继续；时钟从“结果”开始，连续两帧间隔不到 100ms（确认真在播放）才从头播放，所以缩略图、后台标签页、只给一帧的环境直接显示结论（修改前停在空白的 0/16） |
| §9.2 跑道（`dp-m9-race.tsx`） | rAF 里每帧 `setState`，React 每帧改写跑道样式 | 200 帧内 1592 次样式改写 | 每条跑道用 Web Animations 播放 `transform`；React 只在每条跑道到终点时更新一次：0 次逐帧改写 |
| §5.1 / §7.2 自动播放 | 计时器在屏外也继续推进 | 屏外继续走步 | 屏外暂停，回来从原步骤继续 |

没有添加 `will-change`：动画属性已经是 `transform` / `opacity` / 画布绘制，主要问题是不必要的循环与逐帧渲染，这两项已从根源去掉。

## 二、交互节奏

- 按钮已有的按压反馈（`scale(0.97)`，140ms）保留。
- 连续点击、快速反向：画布过渡从当前画面续接（各模块的 approach 缓动可中断），不从头重放。§5.1 的点、连线、数组 D、伪代码高亮与步数都由同一个 `step` 状态驱动；连点 7 次（正反交替、每次间隔 1 帧）后五处一致。
- 滑块与数值跟手：数值本来就同步，现在画布也同步（见上表）。
- 教学播放提供速度选择，不压缩成 UI 短动画：§5.1 自动播放（慢 2.8 s / 中 1.7 s / 快 0.9 s 每步，“选中”一步多停 30%）、§7.2 逐层播放（1.6 / 1.0 / 0.5 s 每层）、§9.2 跑道（最慢一条 6.0 / 3.6 / 1.8 s）。
- 减少动态效果：画布直接显示最终状态，封面不播放，跑道不动画；自动播放仍按所选速度走步（每步是内容切换而不是位移动画）。

## 四、修改前后对比（同一设备、同一操作）

条件：同一台机器、同一浏览器窗格，生产构建，`measure.html?all=1`（全部章节展开），1440×900。
浏览器窗格在后台时真实 `requestAnimationFrame` 与 `IntersectionObserver` 都不触发，所以用 `tools/measure/harness.js`
接管二者：手动推进虚拟帧（每帧 16.7ms）、按 rootMargin 手动计算相交，统计每帧的循环数、屏内 / 屏外重绘数与脚本耗时，
用画布像素摘要判断“多少帧后静止”。操作脚本 `tools/measure/scenarios.js`，原始结果 `tools/measure/results-2026-10-26.json`。

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 停在封面 120 帧 | 22 个循环；每帧屏外重绘 21 张；脚本 55.2 ms/帧（p95 132） | 1 个循环（封面播放中）；屏外 0；3.4 ms/帧（p95 7.5） |
| 停在 §5.1 120 帧 | 22 个循环；屏外 21 张/帧；57.9 ms/帧 | 0 个循环；0 重绘；0.02 ms/帧 |
| 拖动 §3.1 滑块后静止 | 85 帧 | 1 帧 |
| 点 §2.1 场景 B 后静止 | 51 帧（之后循环仍在空转） | 55 帧（900ms 过渡）后循环停止 |
| §5.1 连点后静止 | 58 帧 | 55 帧后停止 |
| §9.2 开跑 200 帧 | 1592 次样式改写；23 个循环 | 0 次；0 个循环 |
| 过渡中途滚走 60 帧 | 23 个循环、屏外 21 张/帧 | 0 个循环、0 重绘；回来时直接是最终画面，所选场景不变 |
| 封面播放 7 秒后 | 23 个循环，封面仍在每帧重绘 | 0 个循环 |

注意：毫秒数是本机后台窗格里、每帧还包含一次 React 提交等待的测量值，只用于前后对比，不代表真机帧时间。
